# 公众号排版兼容处理

预览、主题画廊、复制富文本及 HTML 导出共用 `buildWechatHtml`。预览仅额外添加大纲定位属性；本地图片预览地址与发布占位处理仍按原规则区分，图片未处理不会阻止复制。

## 本次修复

- 行内代码输出为带内联样式的 `span`，避免接收端将正文里的 `code` 识别为代码块；保留代码块的 `pre > code` 与语法高亮。
- 列表中的连续文字、代码和标点包在同一个内容容器中，保留嵌套列表、起始序号和多段列表项。显式输出列表符号、缩进、字号和行高，不依赖编辑器的默认 CSS。
- 列表中的加粗、斜体、删除线也转换为带内联样式的 `span`，减少加粗标签与其后冒号、正文被接收端拆开的风险；链接保留 `a` 与地址，显式设为行内显示。保留用户主动输入的换行和多段结构，不使用禁止换行来掩盖问题。
- 图片说明使用块状显示的 `span`，避免在 `p` 内插入另一个 `p`，造成粘贴时重新解析出空段落。
- 引用样式完成后再调整段落间距，保留多段之间的分隔，只去掉末尾留白。
- 标签标题保留块级标题外壳，内部显示色块；强调文字继承标题色，避免连续标题挤在一行或标签上的文字对比不足。
- 保留 Markdown 表格的左、中、右对齐；单元格显式设置字号和行高。

## 验证

运行 `npm test`，其中 `tests/wechat-markdown.test.mjs` 覆盖 16 套文章主题、4 种标题样式、10 套代码主题，以及 HTML 序列化后重新解析的结构。jsdom 仅为测试依赖，不进入前端运行代码。

`tests/fixtures/clipboard-preview.html` 可通过本地静态服务器打开，用于把真实剪贴板富文本粘贴进 375 px / 760 px 的接收区域。它故意设置不同的默认 CSS，用于回归样式隔离，**不是公众号清洗器或官方模拟器**。

最终仍需在公众号中用新复制的内容验证：替换旧内容 → 保存草稿 → 预览 → 手机检查。重点检查代码与标点是否同行、列表嵌套、代码缩进、长行、表格和图片说明。不要重复粘贴到已经错乱的旧结构里；先保存备份，再替换对应内容。

公众号自身的 HTML 清洗、字体环境、远程图片可用性与发布后的处理不受本工具控制；本地规则检查不能保证发布结果完全一致。
